## Learned

- **Liveness vs readiness.** I mixed these up in my own quiz, so writing it down properly:
  - **Liveness** asks "is this process alive?" If it fails, the platform restarts me, so it must never depend on the database. Otherwise a 30-second database blip restarts every healthy server.
  - **Readiness** asks "should I get traffic right now?" It checks MySQL and whether I'm shutting down. If it fails, the load balancer just stops sending me requests.
- **Request context with AsyncLocalStorage.**
  - The middleware runs the rest of each request inside `requestContext.run({ requestId }, next)`, and that context survives every `await`.
  - pino's `mixin` reads it on each log line, so a service three calls deep logs the request ID without knowing it exists.
  - **For background jobs** I'll have to copy the ID into the job data and call `run()` again in the worker.

## Stuck on

- **Stacked PRs that never reached `main`.**
  - **What happened:** I merged nine PRs, but only two reached `main`. The others merged into their parent branches *after* those parents were already merged, so GitHub never moved them to `main`.
  - **The fix:** one landing PR (#17).
  - **Next time:** merge a stack bottom-up, one PR at a time, and check each child has retargeted to `main` before merging it.
